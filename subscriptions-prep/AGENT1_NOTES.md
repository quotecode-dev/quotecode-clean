## 4. Design deviations / interpretations (flag for Codex review)

1. **Replay passes the quote lock and binding check.** The coordinator's order returns a same-key/same-quote replay immediately.
   I record `replay=true` and continue through the quote lock and the existing-ledger/binding check. A replay for a deleted quote
   then returns `quote_not_found`, and a replay after a customer change returns `customer_changed_new_quote_required`. Without this,
   a replay could authorize output for a different customer while the flag is OFF. The DB tests cover both cases.
2. `get_free_issue_balance.wouldConsume` is true only for the caller's own, unsigned **Draft** with no ledger row (a legacy non-draft
   quote answers false, because the RPC would return `legacy_issue_policy_pending`). The extra field `limitReached` is added for the
   notice.
3. The `quotes` enforcement trigger also refuses an owner (`user_id`) change on an output quote. The `services` trigger also covers an
   owner move on UPDATE; ordinary product edits never count.
4. `provision_free_10` also refuses an account that has ledger history (prevents re-provision after an entitlement row was deleted,
   i.e. no regrant). service_role keeps SELECT/INSERT/UPDATE/DELETE on `account_entitlements` only; on the ledger it has SELECT only;
   on the flags SELECT/UPDATE. All other default privileges are revoked.
5. JS `monthlyPrice` accepts only `market: 'ILS'` (the exact decided pricing market). `'Local'` also throws, so a market is never
   inferred from a weak signal.
6. On the already-authorized path the RPC performs no status change, even for channel `send`. So a quote first output via
   public_share stays Draft until a separate Send status write. Under the flag that write is allowed because a ledger row exists.
   Part of the open "status effect" item.

  ordering and failure handling between the RPC commit and the snapshot write are not designed here (no outbox, no distributed
  transaction).
