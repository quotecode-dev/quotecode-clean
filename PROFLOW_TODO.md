## Permanent Question / Ambiguity Rule

Within any single authorized task, if Claude gets stuck, hits a genuine question, or finds a real ambiguity on one specific sub-item:

1. Document the exact question/problem.
2. Block **only** that sub-item.
3. Continue immediately with the next independent, safe item.

Do **not** stop an entire task/workstream because of one isolated question — record it and keep moving through everything else that is safe and independent of it. The only exception: stop completely if continuing could risk production, security, real customer data, or any other destructive/unrecoverable change — those always warrant a full stop, not just a blocked sub-item.

## 10. Address Display — Country-Aware Formatting

**Status: 🟡 PARTIALLY IMPLEMENTED (working tree, not committed) — meaningful gaps remain, NOT removed from OPEN list per Part 16's own instruction.**

**What was done**: a shared formatter, `src/utils/addressFormat.js` (`formatAddress`), is now the single source of truth for the stored `street|city|state|zip` format. Hebrew: exact owner-approved pattern `רחוב, עיר מיקוד` (comma after street, space — not comma — before the postal code, no `|`) — e.g. `בן אליעזר, רמת גן 5213003`, live-verified via a real disposable TEST quote/business (both the Public Quote header's business address and the recipient block's client address). Applied to: `PublicQuoteHeader.jsx` (business address, both Desktop and Mobile branches), `PublicQuote.jsx`'s recipient block, and `ClientsTab.jsx`'s address column (owner-facing).

**Real, reported limitation (not glossed over)**: **no field anywhere in the schema records which specific country a business or client is in** — only the binary Local/International market classification exists, never a granular country (UK/US/Canada/Australia/etc.). Genuine per-country formatting (the UK/US/Canada/Australia/NZ/Ireland/Singapore/South Africa examples from the original spec) is therefore **not actually implementable** without first capturing a country field somewhere — doing so without that field would mean inventing data that doesn't exist, which this item's own instructions explicitly forbid. What was implemented instead for International is one honest, general fallback (`Street, City, State Zip`, omitting empty parts) that reads reasonably across most English-speaking markets but is **not** genuine country-aware formatting — reported as a limitation, not presented as the full solution.

**Surfaces NOT yet covered** (real gaps, not silently claimed done): ~~`PublicQuoteEn.jsx` has no client address field displayed at all~~ — **superseded, no longer a gap**: item 19's "Public Quote English Terms/Notes + Recipient Contact Parity" pass added the client address to `PublicQuoteEn.jsx`'s recipient card using this same `formatAddress` formatter — confirmed still current via the 2026-08-28 Cross-Market Regression Audit below. `SettingsTab.jsx`/`QuoteForm.jsx` show the raw street/city/state/zip as separate input fields, not a combined display string, so they were not in scope; PDF/print output and email templates were not audited or touched this pass; `UserDetailsModal.jsx` has its own separate, deliberately-brief `formatAddressCity` (Super Admin-only, shows only street+city, not the full address) — left as-is, not unified with the new shared formatter, since it is Admin-only (not customer-facing) and intentionally scoped differently.

**Second finding, FIXED same day**: `PublicQuote.jsx` (Hebrew Public Quote) previously maintained its own private, functionally-identical duplicate of `src/utils/money.js`'s `formatMoney` instead of importing it — unlike `Dashboard.jsx` and `PublicQuoteEn.jsx`, which were already correctly consolidated. **Fixed**: now imports and delegates to the canonical `formatMoney`. ## 24. Attachment `storage_path` Persistence Bug (added 2026-08-30, Full Runtime TEST Build Phase 3 apply task)

**The bug**: new quote-attachment uploads (`Dashboard.jsx`'s upload flow, `~line 2251-2256`) insert `file_name`/`file_url`/`file_size` into `quote_attachments` but never set `storage_path`. **Consequences, recorded explicitly**:
- Newly uploaded attachments may be silently skipped when a Public Quote page resolves its attachment list.
- Affects **both HE and EN identically** — confirmed by both review agents independently; this is shared code with zero market-conditional branch, not a market-specific defect.
- **Pre-existing** — this bug exists in the current application code today, independent of any migration work.
- **NOT caused by** `20260830000003_capture_base_storage.sql` (File 03) or any other Phase 1-3 migration — the Storage bucket/policy layer is unrelated to this application-layer column-population gap.
- **NOT fixed in this task or any Phase 1-3 task** — recording only.
