## Architectural root cause
The classifier was a UNION of phrase-shaped regexes (36 regex definitions in `marketTruth.ts`). Each release fixed one shape (Hebrew prefixes, then plurals) and exposed the next (adverbs inside the copula, quantified subjects, "belongs to" relations, plural Hebrew predicates, punctuation composition) because a regex union encodes surface strings, not the relation between SUBJECT, RELATION and TARGET. Measured on the new compositional sets, the v36 classifier leaked **2,636 of 3,144** English-identity cases, 576 / 616 Hebrew-relationship cases, 140 / 946 override cases, 66 / 684 composition cases and all 11 Codex exemplars - the brittleness was systemic, not six phrases.

## The grammar (`supabase/functions/chat-ai/marketIntentGrammar.ts`, 673 lines; `marketTruth.ts` shrank 284 -> 87 lines and now contains ZERO regular expressions)
`raw text -> NORMALIZE -> SEGMENT -> TOKENIZE + TAG -> PARSE into a normalized intent -> ACCOUNT_MARKET route -> structured truth -> prose`
1. **Normalization**: lower-case, Hebrew points, quote variants, every dash form (en / em / bar / spaced hyphen / double hyphen) -> one clause boundary, Hebrew prefix + hyphen + Latin split.
2. **Clause segmentation**: sentences at `. ; : ! ? -`; each sentence analysed whole AND as comma / conjunction clauses; a question mark is remembered per sentence. A composed message yields several clauses (identity + currency instruction) that normalize like the same clauses written alone.
3. **Tokenize + tag** with a categorized lexicon (SELF, POSS, ENTITY, SURFACE, PERSON, MKT, MNOUN, COP, BELONG, PART, MODAL, ADV, CUR, DESIRE, POSSIBLE, SIM, VERB roles, guards ...): English contractions, plural derivation (lexicon lists singulars only), multi-word units ("belongs to", "seem to be", "as if", "in fact"), quantified selves ("all of us", "every one of us", "the two of us", "both of us", "everyone of us"); **Hebrew clitic morphology** - stems listed once, bare; prefixes (ו/ש + ב/ל/מ/כ + ה) stripped by one analysis, fewest prefixes first (so "שלי" is the possessive, not ש+"לי"; "מחשבון" is a calculator, not מ+"חשבון").
4. **Parse** each clause into `{subject: SELF|ACCOUNT|BUSINESS|PROFILE|NONE, subjectNumber, relation: IDENTITY|BELONGS_TO_MARKET|MARKET_QUERY|MARKET_OVERRIDE_REQUEST|CURRENCY_PREFERENCE|CURRENCY_CAPABILITY|CURRENCY_QUERY|DISPLAY_REQUEST, targetMarket: LOCAL|INTERNATIONAL, targetCurrency: ILS|USD|EUR|GBP|OTHER, modality: ASSERTION|QUESTION|REQUEST|DESIRE|SIMULATION, polarity}`. Every normalized kind resolves to the SAME single route.
- **Supported domain**: identity / belongs-to-market (belong(s) to, is in, is part of, falls under, שייך, נמצא, נכלל, ...) of a SELF / quantified-self / owned account-business-profile subject, with adverbs, modals, participial copulas ("is considered / registered", מוגדר / נחשבים), parenthetical adverbials and scope complements; market override / simulation (verb + SELF-or-owned-account OBJECT + singular or plural predicate); implicit "switch to the local market"; account market attribute changes; currency preference / capability / display request / query.

## CRM / third-party boundary (over-routing prevention)
The parser encodes SUBJECT OWNERSHIP, not nouns: an identity relation needs a SELF or ACCOUNT-owned subject; an override needs an ACCUSATIVE self / owned-account object ("treat US as ...", "אותנו"); the gap between subject, copula and market may hold only adverbs / determiners / negation / modals / prepositions (any other word - "looking for", "support", "add" - breaks it); a customer / client / user that is somebody else's ("my clients", "this client", "for the customer", הלקוח, ללקוח, לקוח שלי) blocks currency intents; sentence-level guards (currency knowledge, digits, price questions, banking, quote creation, charts / widgets).

## Honest limits
The grammar is a deterministic DOMAIN parser over an explicit lexicon, not natural-language understanding. Closure is claimed over the explicit normalized grammar and the tested intent domain, not universally: vocabulary outside the lexicon (an unlisted participle, an unlisted market or person noun, an unusual word order) can still reach the model, which then answers under the account-context block as before. The unseen sets are regression evidence, not a completeness proof; the customer-specific-currency and CRM boundaries are heuristic (subject / object ownership). "Can I create a quote in USD?" is still deliberately not an account-market intent.
